# Skyhook Industries editorial standard

The public site should be ambitious without collapsing different levels of evidence into one another. It should also sound like a description of a machine, not a grant application.

## Claim classes

1. **Flight heritage** — measured or demonstrated in space.
2. **Prior research** — modeled or analyzed by credible aerospace researchers or institutions.
3. **Skyhook study** — a present architectural choice under investigation.
4. **Open target** — a desired value or feature that still depends on modeling, testing, material properties or system trades.

## Evidence rules

- Never use a design target as though it were a validated specification.
- Prefer primary research and mission documentation.
- State conservation-of-momentum and energy consequences explicitly.
- Do not describe electrodynamic reboost as creating energy or as making the complete transportation chain fuel-free.
- Do not imply that a transportation-scale tether closes with heritage polymer fibers unless a structural model supports the claim.
- Keep Skyhook Industries' present study architecture distinct from HASTOL, MXER, cislunar tether and other prior architectures.
- Use calendar dates only when a funded, measurable program justifies them.
- Archive superseded concepts instead of leaving them mixed into current plans.

## Numerical-model rules

- Public calculated values must be traceable to a committed model version or an explicit hand calculation.
- When a number depends on a screening allowance, state the allowance near the result rather than letting it harden into a specification.
- Separate normalized structural results from absolute facility-mass assumptions.
- “Allowable specific strength” means the derated material-system value used for design, not headline ultimate tensile strength divided by density.
- If a model has not propagated a state through time, do not describe an instantaneous osculating orbit or force balance as a safe trajectory.
- Where practical, benchmark simplified models against a published architecture before using them to support a Skyhook conclusion.
- Generated model output should be reproducible in CI so edits to equations or constants cannot silently leave stale public numbers behind.

## Voice rules

- Describe the physical event first: vehicle, tether, motion, load, orbit, release.
- Prefer concrete verbs over abstract nouns. “The tether gives up orbital momentum” is better than “momentum-exchange architecture considerations.”
- Put qualifications where they belong instead of qualifying every sentence.
- Avoid generic startup slogans, consultant language and unexplained aerospace jargon.
- Use diagrams when they can replace a paragraph.
- Do not define the system mainly by what it is not. Explain the machine first; distinguish it from a space elevator second.
- Rigor should make the ambition credible, not make the project sound timid.
